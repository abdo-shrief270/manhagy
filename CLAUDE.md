# منهجي (Manhagy) — notes for AI assistants

E-learning SaaS for teachers and centers in Egypt (later: marketplace, then LMS for schools, institutes, colleges, universities). Product plan: `docs/PLAN.md`. Technical plan: `docs/TECH_PLAN.md` (build order in §13). UI copy is Egyptian Arabic, RTL. Domain: `manhagy.online` (teacher sites `{slug}.manhagy.online`).

## Layout
- `site/` — static landing page for teachers (deployed by `.github/workflows/deploy.yml` with `deploy/setup-server.sh`); `src/` draws its screens, ads and the page (`python3 src/screens.py && node src/render.cjs screens 2`, `src/ads.py`, `src/site.py`; the domain is `DOMAIN` in `src/common.py`). `ADS.md`, `INTERVIEW.md` = the market test.
- `apps/api` — Laravel 13, PHP 8.4, PostgreSQL. The platform kernel copied from Muhasebi (modular monolith `app/Modules/*`, shared kernel `app/Support/*`), with the shop modules removed. Modules kept: Identity, ModuleManager, Billing, Notifications, Messaging, Feedback.

## Rules that tests enforce (`apps/api/tests/Architecture`)
- A module may only reference another module's `Contracts\` and `Events\` namespaces.
- Every model under `app/Modules/*/Models` uses `BelongsToTenant` (or `SharedBetweenTenants`), except the allowlist (Tenant, User).
- Every route of an `Optional` module carries `module:{key}` middleware; every signed-in route checks a permission (`RouteAuthorizationTest`).

## Conventions (same as Muhasebi unless noted)
- New module: `app/Modules/{Name}/module.php` returning a `ModuleManifest`; routes in `routes.php` (auto-prefixed `/api/v1`), migrations in `Database/migrations`, listeners in a `ModuleServiceProvider` `$listen`.
- Cross-module side effects: must succeed with the change → a `Contracts\` interface inside the transaction; otherwise → `EventRecorder::record(...)` + a `ModuleListener`.
- Permissions are declared in manifests and enforced with `can:{key}` / `$user->can()`. Owners have every permission of the modules the account can use. Default roles (`Identity\Support\DefaultRoles`): `manager` (all but roles / audit) and `assistant` (its list is intersected with the permissions that exist, so later modules' keys already sit there).
- Account kind (`Identity\Enums\AccountKind`): teacher | center open at sign-up; institute | school | college | university exist for the LMS phase (not selectable yet). Stored in `tenants.shop_types` / `shop_type` (column names kept from the kernel); manifests' `shopTypes` / `trialFor` use these values. A second branch is for centers only (`branches_for_centers`).
- Billing plans (`config/billing.php`): teacher / pro / center, priced by active students (assumptions; admins change them). No optional module exists yet, so plans, `needs` and module prices are empty lists.
- WhatsApp templates (`Messaging\Support\Templates`): parent_report, parent_absence, student_welcome, renewal_reminder; message subjects learner / guardian / enrollment / exam_attempt / group_session. Notification categories: billing only so far — each module adds its own.
- Curriculum (core `curriculum`, platform-wide, not per account): `curriculum_nodes` through the query builder (`Curriculum\Support\Tree` = `Contracts\CurriculumTree` for reading / suggesting and `Contracts\CurriculumAdmin` for the admins). Levels (`Enums\NodeKind`, also `CurriculumAdmin::KINDS`): stage → grade → (track) → subject → unit → lesson; university → faculty → (department) → year → course → unit → lesson; only the allowed child under each level, roots are stage / university, a name (normalised by `SearchText`) once per parent, no deleting a node with children (`curriculum_has_children`). Status published | review | hidden. Seeded by `Support\EgyptCurriculum` in its migration (stages, grades, tracks, usual subjects, Azhar grades, public universities — a starting point to review; adds only what's missing). Public `GET public/curriculum?parent=`, `/{id}` (+ path, children), `/search?q=&kind=` (every word in the node's path), `/kinds`. Teachers `POST curriculum/suggestions` (`curriculum.suggest`) → status review (same name = the existing node), audited. Admins `GET/POST /admin/curriculum`, `PATCH/DELETE /admin/curriculum/{id}` (AdminLog `curriculum_*`), badge `curriculum` = to review. A course will hang on a teachable node (subject / course / unit / lesson).
- Sites (core `sites`): one `sites` row per account (made on first `GET /site` with address `t-{code}`): slug (`Support\Slugs`: a-z0-9-, 3–30, reserved names), title, tagline, colour (`Directory::COLORS`), `device_limit` (1–5, default 2), `registration_open`, `require_parent_phone`. `GET/PUT /site` (`site.manage`, audited), public `GET public/sites/{slug}`; `services.sites.host` (`SITES_HOST`) gives the URL. Others read `Sites\Contracts\SiteDirectory` (`bySlug`, `forTenant`).
- Learners (core `learners`): a student is one platform-wide `learners` row (phone E.164, password; allow-listed like User) with a per-account `learner_profiles` row (grade = curriculum node, parent phone, consent, notes, blocked) — a teacher never sees another teacher's profile — and per-account `learner_devices` (sha256 of the key the app keeps). `POST public/sites/{slug}/register` (consent required; parent phone when the site asks; a known phone = `phone_taken`) and `/login` (5 wrong tries lock 15 min) → `Support\SignIn`: profile made on first visit (refused `registration_closed` when the site is closed), `learner_blocked`, device limit → 409 `device_limit`; one Sanctum token per device with abilities `learner`, `site:{tenant}`, `device:{id}`. Student routes use `auth:sanctum` + `learner` middleware (`AuthenticateLearner`: sets the tenant from the token, a removed device = 401 `device_removed`, blocked = 403): `GET/PUT learner/me`, `POST learner/logout`. Account side `GET /learners?q=&grade=&blocked=` (`learners.view`), `GET/PATCH /learners/{profile}`, `POST …/block|unblock` (`learners.manage`), `DELETE …/devices/{device}` (`learners.devices`, ends that device's token), all audited. Others read `Learners\Contracts\LearnerDirectory` (`current()`, `find()`). Phone verification (SMS vs a WhatsApp message to the platform) is still to decide.
- Media (core `media`, `media.upload`): `media_assets` (kind video | file, status uploading → processing → ready | failed). Videos live at a provider behind `Media\Contracts\VideoHost` (`createUpload` → the browser uploads straight to it, `status`, `playback(videoId, ttl)` = a short-lived signed URL, `delete`), bound in `MediaServiceProvider` from `services.video.driver` (`VIDEO_DRIVER`; only `fake` exists until the provider is chosen — `FakeVideoHost`, always ready, `VIDEO_FAKE_DURATION`). `POST /media/videos` (title) → upload instructions, `POST /media/{id}/check` asks the provider. PDFs (≤ 50 MB) on the private local disk, `POST /media/files`, served only through `MediaLibrary::fileUrl()` = a temporary signed route `media.file` (no sign-in). Other modules use `Media\Contracts\MediaLibrary` (`find`, `playback` — 409 `video_not_ready` —, `fileUrl`).
- Courses (core `courses`, `courses.view` / `courses.manage`): `courses` on a teachable curriculum node (`curriculum_not_teachable`), price in piasters (0 = free), `access_days` (null = until it closes), draft → published (needs a lesson, `course_empty`; audited) → archived; only a never-published course is deleted (`course_was_published`). A new course gets «الفصل الأول»; `course_chapters` (delete only empty, `chapter_not_empty`), `course_lessons` (kind video | pdf | exam, `media_id` checked against `MediaLibrary` — `lesson_media_invalid` —, `duration_seconds` from the video, `free_preview`, `publish_at`, `requires_previous`, `max_views`, `count_percent` default 70). `PUT /courses/{id}/order` sends every chapter with its lessons (`order_mismatch` otherwise). Others read `Courses\Contracts\CourseCatalog` (`published`, `course`, `outline` = lessons in order with `position` / `previous_id`, `lesson` + `course_status`). Public `GET public/sites/{slug}/courses`.
- Access (core `access`, `access.enroll`): `enrollments` (source manual | code | wallet | free, `ends_at`, revoked with a reason; audited) through `Access\Contracts\Enrollments::grant()` (inside the caller's transaction; an active enrollment is extended from its end), `lesson_progress` (views, `extra_views` from the teacher, watched / pending seconds, last position, completed), `playback_sessions`. `Support\Rules::lockReason()` = the one answer for the outline and for opening: not_yet → not_enrolled (free previews skip it) → previous_required (the nearest earlier non-exam lesson must be completed) → exam_soon (until Assessments) → views_used_up. `Support\Player`: `POST learner/lessons/{id}/open` — PDF = a 5-minute signed file link (counts a view, completes it); video = ends the student's other sessions (`replaced`), a new session + playback link (`VideoHost`, 5 min) + signed watermark {text = name · local phone, issued_at, HMAC} + resume position; `POST learner/playback/{id}/beat` {position, playing} every 60 s renews the link; time is credited by the server's clock (≤ 90 s a beat, nothing while paused), a view counts once `pending_seconds` reach `count_percent` of the duration (once per session; a counted session ends after 2× the duration, `finished`); no beat for 150 s = `expired`; ended → 409 `playback_ended` + `reason`. Student routes (`learner` middleware) pass `RouteAuthorizationTest` by that middleware. Teacher: `GET/POST /enrollments`, `POST /enrollments/{id}/revoke`, `POST /access/extra-views`, `GET /access/progress?learner_id=`.
- Wallet (core `wallet`, `wallet.view` / `confirm` / `adjust` / `settings`): `learner_wallets.balance` (piasters, per account) and the append-only `wallet_transactions` (`seq`; code | transfer | purchase | adjustment) move together only through `Wallet\Contracts\LearnerWallets::post()` under a row lock (below zero → `wallet_insufficient`). Transfers: `wallet_settings` (`transfers_enabled` needs an InstaPay handle or wallet number, `min_topup`) → `POST learner/wallet/topups` (amount, method instapay | wallet | other, proof image → WebP on the private disk; ≤ 3 pending) → bell `wallet.topup_requested` (category `wallet`, `wallet.confirm`) → `/wallet/topups` approve (optionally the amount that actually arrived) / reject with a reason, audited. `POST learner/courses/{id}/buy` = a purchase row + `Enrollments::grant(…, 'wallet')` in one transaction (price 0 = `free`; `already_enrolled` when it never expires). Teacher: `GET /wallet/statement?learner_id=`, `POST /wallet/adjust` (audited). Money text via `Wallet\Support\Money::format()`.
- Codes (core `codes`, `codes.view` / `codes.manage`): `code_batches` (`CB-00001` from `DocumentNumbers`, kind course — `days` overrides the course's — | balance — `value` —, `unit_price` = what a card sells for, count ≤ 2000, `expires_at`, optional distributor, cancellable whole or by card serials, audited) and `codes` (one per card: `serial`, only `hash` = HMAC(app key, tenant|code) — the codes themselves are returned once, in the create response, for printing / export). `Support\CodeFormat`: 12 characters from `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, the last a Luhn mod 31 check character, shown `XXXX-XXXX-XXXX`. `POST learner/codes/redeem` (`Support\Redeemer`): typo → `code_mistyped`, then under the code's row lock invalid / used (says if it was you) / cancelled / expired; course → `Enrollments::grant(…, 'code', days, ref = code id)`, balance → `LearnerWallets::post('code')`; every wrong try counts (5 per student, 20 per IP, 15 min → 429 `code_attempts`). `GET /codes/lookup?code=` tells support what happened to a code. Distributors (`distributors`, kind library | center | assistant | other) + append-only `distributor_payments` (collected; a mistake = a reversal row): `Support\Stats::distributors()` = given / used / unused / cancelled cards, sold (used × card price), collected, due. Lesson-only codes aren't built (a «month» = a course with access_days 30).
- Sidebar groups (`MenuItem::GROUPS`): teaching, learners, sales, center, reports, settings.
- Money is integer piasters; shop data ids are UUIDv7; `DomainRuleException` for business rules; `Auditor::record()` for sensitive actions; don't cache Eloquent models.

## Tests
- `php artisan test` (DB `manhagy_test`, user `manhagy`), `vendor/bin/pint`.
- Module mechanics (trials, plans, permissions, feature switches, listeners, tenancy) are tested with test-only modules in `tests/Fixtures/Modules` (demo, extra, center_tools, reports_plus, web_page, branches), loaded only when `APP_ENV=testing` (`ModulesServiceProvider::paths()`). Billing tests use fixed test plans set in `tests/TestCase.php`, not the real prices.
- `Tests\Concerns\RunsAPlatform::setUpPlatform()` = a teacher with the `mr-mohamed` site, a published course with one video lesson and a registered student (`asStudent()` / `asTeacher()` / `registerStudent()`).
- `Tests\Concerns\SellsInAShop::openShopWithStock()` = a registered teacher account with its owner signed in (name kept from the kernel).
