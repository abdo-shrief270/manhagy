# منهجي (Manhagy) — notes for AI assistants

E-learning SaaS for teachers and centers in Egypt (later: marketplace, then LMS for schools, institutes, colleges, universities). Product plan: `docs/PLAN.md`. Technical plan: `docs/TECH_PLAN.md` (build order in §13). UI copy is Egyptian Arabic, RTL. Domain: `manhagy.online` (teacher sites `{slug}.manhagy.online`).

## Layout
- `site/` — static landing page for teachers (deployed by `.github/workflows/deploy.yml` with `deploy/setup-server.sh`); `src/` draws its screens, ads and the page (`python3 src/screens.py && node src/render.cjs screens 2`, `src/ads.py`, `src/site.py`; the domain is `DOMAIN` in `src/common.py`). `ADS.md`, `INTERVIEW.md` = the market test.
- `apps/api` — Laravel 13, PHP 8.4, PostgreSQL. The platform kernel copied from Muhasebi (modular monolith `app/Modules/*`, shared kernel `app/Support/*`), with the shop modules removed. Modules kept: Identity, ModuleManager, Billing, Notifications, Messaging, Feedback.
- `apps/web` — the teacher's / center's app: Nuxt 4 SPA, Nuxt UI 4, Pinia, the kernel's shell copied from Muhasebi (sign-in + 2FA, assistants and roles, billing, notifications, security, message templates, features). Indigo theme (`--app-accent` amber). Screens: home `/` (`GET /dashboard` + «ابدأ من هنا»), `/settings/site`, `/courses` (+ `CurriculumPicker`), `/courses/[id]` (chapters / lessons / order / publish, `MediaPicker` uploads straight to the provider via `useMediaUpload()`), `/courses/[id]/students`, `/media`, `/learners` + `/learners/[id]` (enrollments, progress + extra views, wallet + adjust, devices, notes, parent report), `/codes` (+ lookup), `/codes/new` (codes shown once: A4 `CodeCards` with QR → `{site}/redeem?code=`, CSV), `/codes/[id]`, `/codes/distributors[/id]`, `/wallet/topups` (proofs fetched as blobs, settings), `/assessments/questions` (`QuestionForm`), `/exams/[lesson]` (settings, questions, results), `/grading`, `/questions`, `/parent-reports` (send one by one on WhatsApp through `useMessages().send()`), `/settings/modules` (trials of optional modules; `module` pages send owners there), `/marketplace` (opt in, headline / about, hide courses, commission due + InstaPay, reviews / commissions tabs), `/certificates` (search, revoke) + `CertificateSettingsCard` on the course page. Center (`definePageMeta({ module: 'center' })`): `/center/groups` (+ `GroupForm` with the weekly times), `/center/groups/[id]` (members, coming sessions, A4 `CenterCards`), `/center/door` (`QrScanner` = BarcodeDetector camera or a scanner that types; every scan / payment goes through `useDoorQueue()` — localStorage queue sent every 5 s and on `online`, device ids —; the roster is cached so names and fees work offline; absentees → `parent_absence`), `/center/cash`, `/center/teachers`. API shapes in `types/manhagy.ts`. Icons named in the API's manifests / script code must be in `icon.clientBundle.icons` (regenerate with the grep in nuxt.config).
- `apps/learn` — the students' site, one SPA for every teacher: the platform is the host's first label on `NUXT_PUBLIC_SITES_HOST` (dev: `?site=` / `NUXT_PUBLIC_DEV_SITE`, kept in localStorage); its colour becomes `primary`. Token per platform in localStorage (`manhagy:learner-token:{slug}`), a random device key per browser (`manhagy:device-key`). Pages: `/` (public courses or «كورساتي»), `/certificates/[code]` (public), course page `CourseCertificate` + `CourseReview` when enrolled, `/me` lists the certificates, `/login`, `/register` (`GradePicker`), `/forgot` + `/verify` (`WhatsappSend`: the wa.me link, polls until the message arrives), `/courses/[id]` (outline with locks, buy from the wallet), `/lessons/[id]` (`VideoPlayer`: hls.js, moving watermark, heartbeat every `beat_seconds`, `playback_ended` overlay, stop with `keepalive` on leave; the dev provider's `.test` links show a demo player; PDFs in an iframe; `LessonQuestions`), `/exams/[lesson]` (server clock offset, answers saved one by one, photo answers, leaves on `visibilitychange`, auto-submit at 0, review), `/redeem`, `/wallet` (transfer proof shrunk before upload), `/me`, `/card` (the center card QR from `learner/center/card`), `/p/[tenant]/[learner]` (the parent's report, no sign-in).
- `apps/admin` — the platform admins' app copied from Muhasebi (shops = accounts, payments, pricing, coupons, partners, sign-up, modules, feedback, errors, server, activity) + «شجرة المناهج» `/curriculum` (browse by parent, search, teachers' suggestions to review, add / edit / hide / delete) + «سوق منهجي» `/market` (accounts owing commissions → details, «سجّل إنه دفع» with the transfer reference, void one; reviews: all / ≤ 2 stars / hidden, hide / show).
- `apps/market` — «سوق منهجي» (`MARKET_DOMAIN`, e.g. courses.manhagy.online; Nuxt SSR, Tailwind only, indigo like the app): `/` (search, kinds مدارس / جامعة / مهارات, roots with counts, top rated / most students / newest), `/search?q&kind&node&price&sort&page` (drill-down chips from `public/market/nodes`), `/courses/{id}` (syllabus, rating distribution, reviews, teacher card, Course JSON-LD; «اشترك من منصة المدرس» = the card's `url` on the teacher's platform with `?via=market`), `/t/{slug}`, `/verify` + `/verify/{code}` (certificates), sitemap / robots. The browser calls its own cached `/api/market/*` handlers (`server/utils/marketApi.ts` → the API with the visitor's IP).
- CI: `.github/workflows/apps.yml` typechecks and builds the four apps.
- `infra/production` (guide: `docs/DEPLOY.md`): Compose — `caddy` (Dockerfile.web builds web / learn / admin as static SPAs + copies `site/`), `api` / `worker` (Horizon) / `scheduler` (FrankenPHP image), `pgsql` 17, `redis`, `backup`. Caddy sites: `APP_DOMAIN` (teachers' app + the API, admin API refused; lesson PDFs may be framed by `*.{SITES_HOST}`), `*.{SITES_HOST}` (learn app; only `/api/v1/public/*` and `/api/v1/learner/*`; on-demand TLS asked of `GET public/sites-tls?domain=` — 200 only for an existing platform), the landing page on the root + www, `ADMIN_DOMAIN` (admin app + admin API, CSP from `scripts/csp.mjs`). `init.sh <root> <email> [nginx]`, `deploy.sh` (backup → migrate → up → horizon:terminate), `ci-deploy.sh` + `.github/workflows/deploy-app.yml` (after api + apps pass, only with `APP_DEPLOY_*` secrets), nginx mode (`compose.nginx.yml` + `nginx-site.conf`, wildcard certificate by DNS challenge). Keep scripts shellcheck-clean.

## Rules that tests enforce (`apps/api/tests/Architecture`)
- A module may only reference another module's `Contracts\` and `Events\` namespaces.
- Every model under `app/Modules/*/Models` uses `BelongsToTenant` (or `SharedBetweenTenants`), except the allowlist (Tenant, User).
- Every route of an `Optional` module carries `module:{key}` middleware; every signed-in route checks a permission (`RouteAuthorizationTest`).

## Conventions (same as Muhasebi unless noted)
- New module: `app/Modules/{Name}/module.php` returning a `ModuleManifest`; routes in `routes.php` (auto-prefixed `/api/v1`), migrations in `Database/migrations`, listeners in a `ModuleServiceProvider` `$listen`.
- Cross-module side effects: must succeed with the change → a `Contracts\` interface inside the transaction; otherwise → `EventRecorder::record(...)` + a `ModuleListener`.
- Permissions are declared in manifests and enforced with `can:{key}` / `$user->can()`. Owners have every permission of the modules the account can use. Default roles (`Identity\Support\DefaultRoles`): `manager` (all but roles / audit) and `assistant` (its list is intersected with the permissions that exist, so later modules' keys already sit there).
- Account kind (`Identity\Enums\AccountKind`): teacher | center | trainer (skills: sells to anyone, courses on the curriculum's field → skill branch) open at sign-up; institute | school | college | university exist for the LMS phase (not selectable yet). Stored in `tenants.shop_types` / `shop_type` (column names kept from the kernel); manifests' `shopTypes` / `trialFor` use these values. A second branch is for centers only (`branches_for_centers`).
- Billing plans (`config/billing.php`): teacher / pro / center, priced by active students (assumptions; admins change them). No optional module exists yet, so plans, `needs` and module prices are empty lists.
- WhatsApp templates (`Messaging\Support\Templates`): parent_report, parent_absence, student_welcome, renewal_reminder; message subjects learner / guardian / enrollment / exam_attempt / group_session. Notification categories: billing only so far — each module adds its own.
- Curriculum (core `curriculum`, platform-wide, not per account): `curriculum_nodes` through the query builder (`Curriculum\Support\Tree` = `Contracts\CurriculumTree` for reading / suggesting and `Contracts\CurriculumAdmin` for the admins). Levels (`Enums\NodeKind`, also `CurriculumAdmin::KINDS`): stage → grade → (track) → subject → unit → lesson; university → faculty → (department) → year → course → unit → lesson; only the allowed child under each level, roots are stage / university, a name (normalised by `SearchText`) once per parent, no deleting a node with children (`curriculum_has_children`). Status published | review | hidden. Seeded by `Support\EgyptCurriculum` in its migration (stages, grades, tracks, usual subjects, Azhar grades, public universities — a starting point to review; adds only what's missing). Public `GET public/curriculum?parent=`, `/{id}` (+ path, children), `/search?q=&kind=` (every word in the node's path), `/kinds`. Teachers `POST curriculum/suggestions` (`curriculum.suggest`) → status review (same name = the existing node), audited. Admins `GET/POST /admin/curriculum`, `PATCH/DELETE /admin/curriculum/{id}` (AdminLog `curriculum_*`), badge `curriculum` = to review. A course will hang on a teachable node (subject / course / unit / lesson).
- Sites (core `sites`): one `sites` row per account (made on first `GET /site` with address `t-{code}`): slug (`Support\Slugs`: a-z0-9-, 3–30, reserved names), title, tagline, colour (`Directory::COLORS`), `device_limit` (1–5, default 2), `registration_open`, `require_parent_phone`. `GET/PUT /site` (`site.manage`, audited), public `GET public/sites/{slug}`; `services.sites.host` (`SITES_HOST`) gives the URL. Others read `Sites\Contracts\SiteDirectory` (`bySlug`, `forTenant`).
- Learners (core `learners`): a student is one platform-wide `learners` row (phone E.164, password; allow-listed like User) with a per-account `learner_profiles` row (grade = curriculum node, parent phone, consent, notes, blocked) — a teacher never sees another teacher's profile — and per-account `learner_devices` (sha256 of the key the app keeps). `POST public/sites/{slug}/register` (consent required; parent phone when the site asks; a known phone = `phone_taken`) and `/login` (5 wrong tries lock 15 min) → `Support\SignIn`: profile made on first visit (refused `registration_closed` when the site is closed), `learner_blocked`, device limit → 409 `device_limit`; one Sanctum token per device with abilities `learner`, `site:{tenant}`, `device:{id}`. Student routes use `auth:sanctum` + `learner` middleware (`AuthenticateLearner`: sets the tenant from the token, a removed device = 401 `device_removed`, blocked = 403): `GET/PUT learner/me`, `POST learner/logout`. Account side `GET /learners?q=&grade=&blocked=` (`learners.view`), `GET/PATCH /learners/{profile}`, `POST …/block|unblock` (`learners.manage`), `DELETE …/devices/{device}` (`learners.devices`, ends that device's token), all audited. Others read `Learners\Contracts\LearnerDirectory` (`current()`, `find()`). Phone verification (SMS vs a WhatsApp message to the platform) is still to decide.
- Media (core `media`, `media.upload`): `media_assets` (kind video | file, status uploading → processing → ready | failed). Videos live at a provider behind `Media\Contracts\VideoHost` (`createUpload` → the browser uploads straight to it, `status`, `playback(videoId, ttl)` = a short-lived signed URL, `delete`), bound in `MediaServiceProvider` from `services.video.driver` (`VIDEO_DRIVER`; only `fake` exists until the provider is chosen — `FakeVideoHost`, always ready, `VIDEO_FAKE_DURATION`). `POST /media/videos` (title) → upload instructions, `POST /media/{id}/check` asks the provider. PDFs (≤ 50 MB) on the private local disk, `POST /media/files`, served only through `MediaLibrary::fileUrl()` = a temporary signed route `media.file` (no sign-in). Other modules use `Media\Contracts\MediaLibrary` (`find`, `playback` — 409 `video_not_ready` —, `fileUrl`).
- Courses (core `courses`, `courses.view` / `courses.manage`): `courses` on a teachable curriculum node (`curriculum_not_teachable`), price in piasters (0 = free), `access_days` (null = until it closes), draft → published (needs a lesson, `course_empty`; audited) → archived; only a never-published course is deleted (`course_was_published`). A new course gets «الفصل الأول»; `course_chapters` (delete only empty, `chapter_not_empty`), `course_lessons` (kind video | pdf | exam, `media_id` checked against `MediaLibrary` — `lesson_media_invalid` —, `duration_seconds` from the video, `free_preview`, `publish_at`, `requires_previous`, `max_views`, `count_percent` default 70). `PUT /courses/{id}/order` sends every chapter with its lessons (`order_mismatch` otherwise). Others read `Courses\Contracts\CourseCatalog` (`published`, `course`, `outline` = lessons in order with `position` / `previous_id`, `lesson` + `course_status`). Public `GET public/sites/{slug}/courses`.
- Access (core `access`, `access.enroll`): `enrollments` (source manual | code | wallet | free, `ends_at`, revoked with a reason; audited) through `Access\Contracts\Enrollments::grant()` (inside the caller's transaction; an active enrollment is extended from its end), `lesson_progress` (views, `extra_views` from the teacher, watched / pending seconds, last position, completed), `playback_sessions`. `Support\Rules::lockReason()` (also `Contracts\LessonAccess`, messages in `LessonAccess::MESSAGES`) = the one answer for the outline and for opening: not_yet → not_enrolled (free previews skip it) → previous_required (the lesson just before must be completed — an exam by submitting it) → views_used_up. `Support\Player`: `POST learner/lessons/{id}/open` — PDF = a 5-minute signed file link (counts a view, completes it); video = ends the student's other sessions (`replaced`), a new session + playback link (`VideoHost`, 5 min) + signed watermark {text = name · local phone, issued_at, HMAC} + resume position; `POST learner/playback/{id}/beat` {position, playing} every 60 s renews the link; time is credited by the server's clock (≤ 90 s a beat, nothing while paused), a view counts once `pending_seconds` reach `count_percent` of the duration (once per session; a counted session ends after 2× the duration, `finished`); no beat for 150 s = `expired`; ended → 409 `playback_ended` + `reason`. Student routes (`learner` middleware) pass `RouteAuthorizationTest` by that middleware. Teacher: `GET/POST /enrollments`, `POST /enrollments/{id}/revoke`, `POST /access/extra-views`, `GET /access/progress?learner_id=`.
- Wallet (core `wallet`, `wallet.view` / `confirm` / `adjust` / `settings`): `learner_wallets.balance` (piasters, per account) and the append-only `wallet_transactions` (`seq`; code | transfer | purchase | adjustment) move together only through `Wallet\Contracts\LearnerWallets::post()` under a row lock (below zero → `wallet_insufficient`). Transfers: `wallet_settings` (`transfers_enabled` needs an InstaPay handle or wallet number, `min_topup`) → `POST learner/wallet/topups` (amount, method instapay | wallet | other, proof image → WebP on the private disk; ≤ 3 pending) → bell `wallet.topup_requested` (category `wallet`, `wallet.confirm`) → `/wallet/topups` approve (optionally the amount that actually arrived) / reject with a reason, audited. `POST learner/courses/{id}/buy` = a purchase row + `Enrollments::grant(…, 'wallet')` in one transaction (price 0 = `free`; `already_enrolled` when it never expires). Teacher: `GET /wallet/statement?learner_id=`, `POST /wallet/adjust` (audited). Money text via `Wallet\Support\Money::format()`.
- Codes (core `codes`, `codes.view` / `codes.manage`): `code_batches` (`CB-00001` from `DocumentNumbers`, kind course — `days` overrides the course's — | balance — `value` —, `unit_price` = what a card sells for, count ≤ 2000, `expires_at`, optional distributor, cancellable whole or by card serials, audited) and `codes` (one per card: `serial`, only `hash` = HMAC(app key, tenant|code) — the codes themselves are returned once, in the create response, for printing / export). `Support\CodeFormat`: 12 characters from `23456789ABCDEFGHJKMNPQRSTUVWXYZ`, the last a Luhn mod 31 check character, shown `XXXX-XXXX-XXXX`. `POST learner/codes/redeem` (`Support\Redeemer`): typo → `code_mistyped`, then under the code's row lock invalid / used (says if it was you) / cancelled / expired; course → `Enrollments::grant(…, 'code', days, ref = code id)`, balance → `LearnerWallets::post('code')`; every wrong try counts (5 per student, 20 per IP, 15 min → 429 `code_attempts`). `GET /codes/lookup?code=` tells support what happened to a code. Distributors (`distributors`, kind library | center | assistant | other) + append-only `distributor_payments` (collected; a mistake = a reversal row): `Support\Stats::distributors()` = given / used / unused / cancelled cards, sold (used × card price), collected, due. Lesson-only codes aren't built (a «month» = a course with access_days 30).
- Assessments (core `assessments`, `assessments.view` / `manage` / `grade` — grading is for the later essay questions): the bank `questions` per course (optional chapter from `CourseCatalog::chapters()`; kind mcq — `options` sent as texts, stored `[{id: a…, text}]`, `correct` = index → `answer` = the option id — | true_false | fill — `accepted` texts, compared after `SearchText::normalize()` —; points, difficulty; answered ones can't change their answer, `question_answered`; in an exam / answered = retired, else deleted). `exams` (one per course lesson of kind exam, `PUT /assessments/exams/{lesson}`: duration, opens / closes, attempts, shuffle questions / options, pass %, `show_answers` after_submit | after_close | never, `exam_questions` with points; the questions are frozen once anyone started, `exam_has_attempts`). `Support\Sitting`: `POST learner/exams/{lesson}/start` (the lesson's locks via `Access\Contracts\LessonAccess`, then `exam_not_ready` / `exam_not_open` / `exam_closed` / `attempts_used_up`; an open attempt is resumed) fixes `ends_at` = start + duration (≤ closes_at) and a `seed` (order by sha256(seed|id), same on return, different per student); answers saved one by one (`PUT learner/attempts/{id}/answers/{question}`, graded at once, `answer_invalid`), up to `GRACE_SECONDS` (10) late; then the attempt is submitted for the student (`submitted_by: timer`, also `assessments:close-expired` every minute) and further answers get 409 `attempt_closed`. `…/leave` counts leaving the page. Submitting marks the exam lesson completed (`LessonAccess::complete`, so requires_previous works through exams); `GET …/result` shows the review only per `show_answers`. Access's `open` on an exam lesson answers `{kind: exam}`. Teacher: `GET /assessments/exams/{lesson}/results` (summary, attempts with leaves, questions hardest first).
- Reports (core `reports`, `reports.view` / `reports.money`): `GET /dashboard` = `Reports\Support\Dashboard` (read-only SQL with an explicit tenant_id over the other modules' tables, Cairo today / month, cached 30 s): money in (used codes × card price + approved transfers; only with reports.money), students (total, new, active this week, enrolled), watching (counted views, hours, watching now, top lessons), exams this week, transfers waiting (with wallet.confirm), and `sharing` = students whose playback in the last day came from 2+ networks or devices.
- Phone confirmation (Learners, `Support\PhoneChecks`, platform-wide `learner_phone_checks` through the query builder): the student SENDS a WhatsApp message to the platform's number (`VERIFY_WHATSAPP`; empty = off, everything open) — nothing is sent to them. Register returns `verification` {code (6 digits, HMAC-stored, 30 min), text, link `wa.me/…?text=`}; `POST/GET learner/phone/verify` = a new code / poll. Meta's Cloud API webhook `GET|POST public/whatsapp/webhook` (handshake with `WHATSAPP_VERIFY_TOKEN`, messages signed `X-Hub-Signature-256` with `WHATSAPP_APP_SECRET`, else 404/403) confirms the check whose phone = the sender and code = a 6-digit run in the text (Arabic digits too) → `learners.phone_verified_at`; with `WHATSAPP_TOKEN` + `WHATSAPP_PHONE_ID` `Jobs\SendWhatsappReply` answers in that chat. Forgot password: `POST public/sites/{slug}/password/forgot` (same answer for any phone) → message → `…/password/reset` {phone, code, password} (409 `reset_not_confirmed` before the message; signs out every device, counts as confirmed). `learner.verified` middleware (403 `phone_unverified`) on open lesson, redeem, buy, top-up, exam start.
- Manual grading (Assessments): question kinds `essay` (text ≤ 5000) and `photo` (`POST learner/attempts/{id}/answers/{question}/photo` → WebP on the private disk) have no stored answer (`explanation` = the model answer); their `attempt_answers.correct` stays null until graded, the attempt keeps `pending_grading`. Queue `GET /assessments/grading` (`assessments.grade`, oldest first, `?graded=1` the done ones, `meta.waiting`), `GET …/grading/{answer}/photo`, `POST …/grading/{answer}` {points ≤ the question's, comment} → recomputes score / percent, `graded_at` when none left; the review shows `points_awarded` + `comment`.
- Parent reports (Reports, `reports.parents`): `Support\ParentReport::build()` (read-only SQL: active courses, lessons watched in the last N days with minutes, published lessons not completed, exams) + `link()` = the student site's `/p/{tenant}/{learner}?days&expires&signature` carrying a relative signed route (`signed:relative`, 14 days) to `GET public/parent-report/{tenant}/{learner}`. `GET /parent-reports?days=7` = every enrolled, unblocked student with a parent phone + the `parent_report` template's variables (`message`, link included) for the web to send and log; `GET /parent-reports/{learner}`. Sites' `toSummary()` carries `url`.
- Engagement (core `engagement`, `engagement.answer`): `lesson_questions` (body, optional video `position`, open → answered | hidden, `public` = every student of the lesson sees the answer, asker shown by first name). Student: `GET/POST learner/lessons/{lesson}/questions` (the lesson's locks via `LessonAccess`, ≤ 10 open, `questions_open_limit`) → bell `engagement.question` (category `questions`). Inbox `GET /engagement/questions?status=`, `POST …/{id}/answer` {answer, public}, `…/hide`.
- Center (optional `center`; trial for center accounts, in the `center` plan, 299 ج/month extra for teachers; `center.door` — assistants too —, `center.manage`, `center.cash`): `center_teachers` (contacts with `share_kind` percent of collected | per_student per attendance), `center_groups` (teacher or the account itself, grade, optional online course, room, `schedule` [{day 0–6 Sunday first, time Cairo, minutes}], `session_fee` / `monthly_fee`, capacity), `center_members` (plan session | monthly; leaving sets `left_at`), `center_sessions` (`Support\Timetable::ensureAhead` = the next 7 days from the schedule, on create / edit and the daily `center:schedule`; `current()` = the one starting within ±1–3 h, else one opened now), `center_attendances` (id = the scanning device's uuid, unique per session + student, late after 15 min), append-only `center_payments` (id from the device; kind session | month with `period` YYYY-MM; the collector's drawer until a `center_handovers` row records expected / counted / difference, audited), `center_settlements` (`Support\Shares::statement` for a period: attendances, collected, due, paid). Cards: `Support\Cards` token = the student's id + a 16-char HMAC (account + student); `GET /center/cards?group_id=` to print, `GET learner/center/card` on the student's phone. Door: `POST /center/scans` {scans: [{id, session_id, token | learner_id, scanned_at, pay?: {id, kind, amount}}]} ≤ 300, each answered ok | duplicate | unknown_card | unknown_session with `owes`; resending changes nothing. `GET /center/sessions/today`, `GET /center/sessions/{id}` (roster: present / late / owes / parent phone; visitors too), `POST /center/groups/{id}/open`. Drawers: `GET /center/cash` (mine), `GET /center/cash/all`, `POST /center/handovers`. Teachers: `GET /center/teachers?from&to` (with statements), `POST …/{id}/settlements`.
- Curriculum skills branch: roots `field` (مجال) → `skill` (مهارة, teachable) → unit → lesson, seeded by `EgyptCurriculum::seedSkills()` (programming, design, marketing, office, languages, Quran, hobbies).
- Marketplace (core `marketplace`, `marketplace.manage`; `/marketplace`): `market_settings` per account (`listed` off until the teacher opts in, `headline`, `about`, `hidden_courses`). `market_courses` = the search table (one row per listed published course with lessons: teacher / site slug + url + colour, title, `search_name` = SearchText of title + curriculum path + teacher, price, `node_ids` uuid[] = the path for subtree filters, `root_kind` stage | university | field, lessons, previews, students, rating, reviews), rebuilt only from contracts by `Support\Indexer` (`Courses\Contracts\MarketCourses` forTenant / changedSince / syllabus, `CurriculumTree::path`, `Enrollments::studentCounts`, `SiteDirectory`, own reviews): per account on saving the settings, `market:sync` every 5 min (accounts whose courses / chapters / lessons changed, mark in cache), `market:sync --all` nightly. An account is out while `blocker()` = not_listed | subscription (`SubscriptionStanding::listed`) | unpaid. Public `public/market` (home), `/courses` (`Support\Search`: every word ILIKE on `search_name`, node subtree, kind school | university | skills, price free | paid, min / max, teacher, sort relevance (pg_trgm similarity) | rating | students | new | price_asc | price_desc, 24 a page), `/courses/{id}` (+ syllabus, reviews, distribution, more from the teacher), `/teachers/{slug}`, `/nodes?parent=` (tree children with listed-course counts). Reviews: `course_reviews` (one per student and course, 1–5 + comment, first name, `hidden` by the admins) via `GET/PUT learner/courses/{id}/review` (`Enrollments::wasEnrolled`, else `review_not_enrolled`); `Indexer::refreshRating` after each. Commission: Wallet's `CoursePurchased` event (`via` from the buy request; the learn app keeps `?via=market` per course 30 days in localStorage, `utils/attribution.ts`) → `Listeners\RecordMarketSale` → `market_commissions` (`seq`; only when `via = market` and the course is in `market_courses`; `services.market.commission_percent` 15, rounded; codes and the teacher's own link pay none). Due ones older than `pay_within_days` (30) take the account out of the market; the teacher sees what's due + the platform's InstaPay (`billing.instapay`); admins settle all at once with a reference or void one (`Marketplace\Contracts\MarketAdmin`, `AdminMarketController` `/admin/market/*`, AdminLog, badge `market` = overdue accounts). `services.market.url` (`MARKET_URL`) = links in the app.
- Certificates (core `certificates`, `certificates.manage`; `/certificates`, card on the course page): `certificate_settings` per course (enabled, optional `min_exam_percent`, title, signer). `Support\Issuer`: eligible = enabled + ever enrolled + every outline lesson completed (`LessonAccess::completed`) + each exam's best fully graded percent ≥ the minimum (`Assessments\Contracts\ExamResults::bestPercents`). `GET/POST learner/courses/{id}/certificate` (status / claim, idempotent, `certificate_not_offered` / `certificate_not_earned`), `GET learner/certificates`. `certificates` keeps a copy of the names, minutes of video, average exam percent, a 10-character code (no look-alikes, shown `XXXXX-XXXXX`); public `GET public/certificates/{code}` (any case / dashes) → the learn app's `/certificates/{code}` (A4 landscape print, QR to itself, WhatsApp) and the market's `/verify/{code}`. The teacher revokes with a reason (audited; the page says so).
- Sidebar groups (`MenuItem::GROUPS`): teaching, learners, sales, center, reports, settings.
- Money is integer piasters; shop data ids are UUIDv7; `DomainRuleException` for business rules; `Auditor::record()` for sensitive actions; don't cache Eloquent models.
